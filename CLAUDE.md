# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**boonsh** is a Windows-only desktop app (Tauri v2 + React 19 + TypeScript + Vite) that combines a graphical file manager with an embedded interactive PowerShell terminal. The product spec is in `boonsh-PRD.md`.

## Commands

- `npm run tauri dev`: runs the full desktop app. Tauri starts Vite on port 1420 (`beforeDevCommand`) and compiles the Rust backend.
- `npm run tauri build`: builds the release `boonsh.exe` plus installers (runs `tsc && vite build` first).
- `npm run build`: type-checks and builds the frontend only. This is the quickest way to check TS changes.
- `cargo check --manifest-path src-tauri/Cargo.toml`: type-checks the Rust backend only.

- `cargo test --manifest-path src-tauri/Cargo.toml --lib`: runs the Rust unit tests. That covers the search parser (`search`), bulk rename (`bulk_rename`) and a few file operations; add the module name to run just those.

There's no frontend test suite, linter or formatter config. `npm run dev` alone serves the UI in a browser, but every `invoke` call fails outside Tauri, so it is only good for layout work.

## Architecture

**Frontend ↔ backend boundary.** The UI talks to Rust only through `invoke('<command>', {...})` from `@tauri-apps/api/core`. Every command is registered in `src-tauri/src/lib.rs` (`generate_handler!`). To add a command, write the `#[tauri::command]` fn in `pty.rs` or `fs_ops.rs` and add it to that list. Tauri maps camelCase JS argument keys to the snake_case Rust parameters (`targetPath` → `target_path`). The Rust structs serialize with snake_case field names, and `src/types.ts` mirrors them by hand (`is_dir`, `modified_timestamp`, and so on). Update both sides together.

**Terminal (`src-tauri/src/pty.rs` + `src/components/TerminalPanel.tsx`).**
- One global PTY lives in `PtyState` (Tauri managed state), created with `portable-pty`/ConPTY.
- `pty_spawn` picks the first shell it finds on PATH: `pwsh.exe`, then `powershell.exe`, then `cmd.exe`. It overrides the prompt to show `USERNAME > ` or `admin > `. Each prompt also emits an invisible OSC `9;9;<cwd>` sequence.
- A background thread streams output to the frontend as the global `pty-output` event. xterm.js (`@xterm/xterm` + `@xterm/addon-fit`) writes it to the screen and sends keystrokes back through `pty_write`.
- Resizing is done by `fitAddon.fit()` followed by `pty_resize`. It fires from a ResizeObserver, from window resize, and from several staggered timeouts after startup. The timeouts are deliberate: they stop the prompt from being clipped while the window is still maximizing.
- Only the `@xterm/*` packages are used, including `@xterm/xterm/css/xterm.css` imported in `index.css`. Don't reintroduce the legacy `xterm` package.

**GUI ↔ shell directory sync.** `App.tsx` owns all app state: current path, items, selection, sort, view mode, and panel sizes. The sync runs both ways:
- GUI → shell: `handleNavigate` calls `list_directory` and writes `cd "<path>"\r` into the PTY.
- Shell → GUI: `TerminalPanel` registers an xterm OSC 9 handler that passes the prompt's reported cwd to `App.handleShellCwdChange`. That handler refetches only when the path (compared case-insensitively) differs from `lastRequestedPathRef`, so a GUI-initiated `cd` doesn't load the folder twice. If you change the prompt strings in `pty.rs`, keep the OSC sequence. Sorting (folders first, natural numeric name order) runs on the client in `App.tsx`. The backend's `natural_cmp` covers its own ordering.

**Selection & clipboard (`App.tsx`).**
- `selectedItem` is the *focused* item, which drives the preview, window title and status bar. `selectedPaths` is the full multi-selection.
- Click, Ctrl+Click and Shift+Click go through `handleItemClick`. Shift ranges start from `selectionAnchorRef` and follow the sorted order.
- Cut/copy is kept inside the app (`clipboard` state), not on the Windows clipboard. `pasteClipboard` calls `paste_items`, then selects the pasted items through `fetchDirectory(path, selectPaths)`.
- All shortcuts run through one window listener that calls `keyHandlerRef`. Ctrl+A/C/X/V and Delete are skipped when focus is in an input or textarea, which includes the terminal, so they reach the shell there.

**File ops (`src-tauri/src/fs_ops.rs`).**
- Uses `std::fs`, `walkdir` (for `search_files` with `*.ext` / wildcard matching) and `trash` (Delete moves items to the Recycle Bin).
- `paste_items` is an async command that does its work in `spawn_blocking`. It never overwrites: clashing names become "x - Copy" when copying and "x (2)" when moving. A move across drives falls back to copy-then-delete.
- `compress_to_zip` and `extract_zip` are built on the `zip` crate with Deflate only (default features are off to keep the binary small). Both are async, use `spawn_blocking`, and use `unique_target` so they never overwrite. Extraction always goes into a new folder, and `ZipArchive::extract` cleans entry paths so they can't escape it. Zip timestamps are local time, converted from Win32 in `zip_datetime`.
- `list_directory` and `pty_spawn` share `default_start_dir()` when no path is given. It returns the folder from the first CLI argument (`boonsh.exe "C:\some\dir"`) if there is one, else `%USERPROFILE%\Downloads`, else the process cwd.
- The file hand-rolls its Win32 FFI (`user32`/`kernel32`/`advapi32` `extern` blocks) instead of pulling in a `windows` crate.

**Search (`src-tauri/src/search.rs`).**
- The search box accepts a small query language. Terms are separated by spaces and all must match: plain name terms, `filename:<regex>` (regex-lite), `filesize:`, `filetype:` and `filedate:`.
- The `filename:` samples in `FEATURES_SPEC.md` ("Regular expressions") are backed by `search::tests::regex_samples`. If you change the regex handling or a sample, update the test and the manual together.
- `path:` (`Filter::Path(Expr<PathNeedle>)`) and `input:` share one expression grammar (`scan_expr` -> `Tok`, `parse_expr`/`parse_or`/`parse_and` -> `Expr<T>`): `,` is OR, a `+` that starts a word is AND, **AND binds tighter than OR, equal operators go left to right**, `( )` group (a `(` opens only at the start of a word, a `)` closes only while one is open, so `setup(1)` stays text). Empty alternatives and a lone `+` are ignored while typing; two words with no operator between them are an error. `parse()` joins the space-separated query tokens of a `path:`/`input:` value (after a comma, before a `+word`, and while a `(` is open). The `path:` leaf checks the full absolute path of the entry (`Candidate.path`, from `entry.path()` in `search_blocking`), lowercase, `/` treated as `\`. Unquoted items are substrings (`Contains`); any item with quotes is `Names`: the whole text (quoted text is literal, so a `*` inside quotes is just a character; `*` outside quotes is a wildcard) split on `\` into consecutive whole folder/file names, each matched with `glob_match` over `Pat` (`Lit`/`Star`); an unquoted item with `*` is `Pattern`, without is `Contains`. `x,y` / `x, y` / `x ,y` / `x , y` are OR; `x +y` (a token that starts with `+`) is AND; `x+y` is literal and a lone `+` is skipped. `tokenize` now keeps quotes in the token (`'` opens a quote only at the start of a piece or after `: , +`, so apostrophes in words are safe) and `parse` joins comma lists and `+` clauses for `path:`/`filetype:`/`type:`/`ext:`; `unquote` strips them for the other filters. A term wrapped in quotes as a whole (`"filename:^my report"`) is still unquoted before the key is read (the manual's regex samples rely on it). Tests: `search::tests::path_filter`, `fs_ops::tests::path_search_finds_files_by_their_folders`.
- `input:` is not a filter: `parse` puts its places in `Query.inputs: Option<Expr<InputSpec>>` (`InputSpec::Path`, or `::Var` for an item that is exactly `{NAME}`); extra `input:` terms are ANDed. It is rejected with `!`. `search_files` returns `SearchResponse { items, notice }` and takes the Global Var values from the frontend (`vars`, from `pathVarsRef`). `resolve_inputs` turns it into `Places = Expr<Vec<PathBuf>>` (a var expands to one leaf with all its paths): it resolves relative places against `dir` (`normalize_path`, no `\\?\`), errors for a missing place, and **skips a var with no value** (collected in `missing`, shown as an amber `search-notice-bubble` via `input_notice`; the rest of the expression is used, nothing left = search the current folder, and with no other terms the plain folder listing). `search_places`/`eval_places` evaluate the tree: a leaf is `search_roots` (a file root is its own single result, `seen_paths` dedupes, `limit` caps), OR is the union, AND keeps only items whose **file name** (case-insensitive, last path component) occurs on every side, listing every copy; with an AND, 5,000 per leaf are collected before the final 300. `search_blocking` is the one-root wrapper used only by tests. The frontend re-runs the search when `currentPath` or the variables change, only while the query contains `input:` (`searchInputKey` in `App.tsx`). Tests: `search::tests::input_places`, `fs_ops::tests::input_places_set_where_to_search`.
- `!` in front of a term negates it. `name:`, `size:`, `type:`, `ext:` and `date:` are short aliases.
- `parse` turns a bad query into a readable `Err`, which the search box shows. A filter with no value yet is ignored.
- `search_files` runs async in `spawn_blocking`, goes at most 8 levels deep and returns at most 300 results. A newer search cancels the older one through `SEARCH_GENERATION`.
- Folder sizes: when `Query::wants_folder_sizes()` is true (a size filter plus a non-negated `type:folder`), `search_blocking` walks the whole tree `contents_first` and adds sizes up from the bottom (`depth_sums`). That scan has no depth limit, so totals are exact; the depth limit only decides which folders count as results. Folder results carry the total in `size` and `size_formatted`. Without `type:folder`, size filters match files only, which avoids surprise full-tree scans. Tests are in `fs_ops::tests` and `search::tests`.
- The frontend waits 250ms after the last keystroke and applies only the newest response (`searchSeqRef`). The `?` cheat sheet lives in `SEARCH_EXAMPLES` in `HeaderBar.tsx`, so keep it in sync with the parser.

**Bulk rename (`src-tauri/src/bulk_rename.rs`, `src/components/BulkRenameDialog.tsx`, `src/bulkRename.ts`).**
- Engine, in a pure module like `search.rs`: `RenameRules { rules: Vec<RuleSpec>, on_collision }` where `RuleSpec` is a serde-tagged enum (`kind`: find, case, insert_remove, numbering, extension, template). The rules run **in list order, and a kind may repeat**. A rule that does nothing (an empty Find, a Remove count of 0, an empty template) compiles to nothing and is skipped. → `compute_name` (counters are keyed per rule position and folder, in `Counters`); `validate_pairs` (shared by preview and apply); `plan_ops` (turns the renames into ordered single renames); `execute_ops` (rolls back if one fails); `undo_blocking`.
- `plan_ops` relies on targets being unique, which `validate_pairs` guarantees. Each rename depends on at most one other, so the dependencies form chains and cycles. Chains are emitted dependency-first, a cycle goes through a `.boonsh-tmp-…` name, and chains are sorted deepest-folder-first so a folder's contents are renamed before the folder itself.
- The undo journal is the executed list of single renames (`Op { from, to }`, temporary renames included). Undo replays it reversed with swapped ends. Don't replan on undo.
- Commands: `bulk_rename_preview` (computes; returns only changed rows), `bulk_rename_validate` (re-checks ticked rows), `bulk_rename_apply`, `bulk_rename_undo`. Find & Replace reuses regex-lite: plain mode uses `regex_lite::escape` and `NoExpand`; regex mode passes the replacement through so `$1` / `${1}` / `$$` work.
- UI rule: the preview is on demand, and any rule edit marks it **stale**, which disables Rename until Preview runs again (`stale` in the dialog). Don't add live previewing. History is `localStorage` key `boonsh_rename_history` (last 5 batches, ~2 MB cap). Saved presets are `boonsh_rename_presets` (up to 30). `normalizeForm` in `bulkRename.ts` converts presets saved in the old fixed-slot shape (`findOn`, `caseOn`...) to the rule list, so keep it when the form shape changes again. Built-in presets live in `BUILTIN_PRESETS`. The dialog edits a list of `RuleForm`s (`RuleCard.tsx` renders one rule of any kind); the TS DTO in `bulkRename.ts` must match the Rust `RuleSpec` (a test, `rules_wire_format_matches_the_dialog`, checks the JSON). Rules that are off fold up (CSS `.br-card.off`). `diffSegments` (LCS) drives the red/green highlighting.
- Template rule: tokens are parsed in `parse_template` (`{name} {ext} {parent} {n} {n:N} {date[:fmt]} {today[:fmt]}`, `{{`/`}}` literal); the date comes from the item's modified time through `localtime`. With `apply_to: "name"` the result replaces only the name part and the extension is kept.
- "If a new name is already taken" is `RenameRules.on_collision` (`CollisionPolicy`: `Skip` is the default, `Block`, `Number`). It is handled in `preview_blocking` only; apply uses the previewed names. `find_skips` (Skip) repeats until nothing new is skipped, because a skipped item keeps its own name in use. `resolve_duplicates` (Number) drops rows whose resolved name equals the current name. Skipped rows are returned with `skipped: Some(reason)`, are never ticked, and are counted in `PreviewResult.skipped`. Presets saved with the old yes/no `autoNumberDuplicates` are converted by `normalizeForm` (true becomes `number`, false becomes `skip`).
- "Include sub-folders": `preview_blocking(paths, rules, include_subfolders)` calls `expand_paths`, which adds everything inside each selected folder (sorted by name, each folder followed by its contents, duplicates removed, links not entered, capped at `MAX_ITEMS`). The dialog's checkbox is not part of the saved form (presets) and defaults to off. One selected folder can open the dialog from the right-click menu (`openBulkRename` in `App.tsx` allows 2+ items or one folder).
- F2: one selected item bumps `renameTrigger`, which opens the single Rename box in `MainFilePanel`; two or more open the dialog.
- Testing in the real app: find a rule card by its `.br-card-title` text, not the card's text (the Find card's dropdown also contains the word "Extension"). **The test app shares browser storage with `npm run tauri dev`** (same `localhost:1420` origin), so a test must back up and restore `boonsh_rename_presets` / `boonsh_rename_history` instead of clearing them. F2 opens the dialog and Ctrl+Z undoes, through `keyHandlerRef` in `App.tsx`.
- Tests: `bulk_rename::tests` (rollback test uses an exclusively-locked file, Windows only). Update `FEATURES_SPEC.md` ("Bulk rename") when behavior changes.

**{SELEC} / {DEST} (`src/pathVars.ts`, `App.tsx`, `MainFilePanel.tsx`, `TerminalPanel.tsx`).**
- Two layers. **Definitions** (`GlobalVarDef` in `src/globalVars.ts`: `id`, `name`, `takes` = `selection` | `item`, `description`) are saved under `boonsh_global_vars`; defaults are SELEC (selection) and DEST (item), both editable and deletable. **Values** are `pathVars` in `App.tsx`, a `Record<NAME, absolute paths[]>`, memory only by design (gone on close). Settings edits definitions through `handleGlobalVarsChange` in `App.tsx`, which matches by `id`: a rename moves the value and rewrites `{OLD}` in the commands' `insertText`/`usage` (`renameInText`), a delete drops the value, and the pending prompt line is abandoned.
- The right-click entry is one submenu, **Assign to Global Var** (`showVarSubmenu` in `MainFilePanel`), listing every definition; `takes` decides whether it stores the selection or the clicked item (empty space: the current folder). The terminal's **Global Var** button is hidden when no variable has a value and lists only those that do.
- Settings (`SettingsPanel.tsx`) has a left bar with **Commands** (groups as tabs) and **Global Var**.
- `pathVars.ts` is pure: `expandTemplate` replaces set variables and leaves unset ones literal; `displayPath` is relative (`.\x`) only inside the current folder, else absolute; `quotePath` adds PowerShell double quotes. Only `{NAME}`s that are defined and have a value are replaced; `hasPlaceholder(text, names)` decides whether a template is kept as the pending line.
- Command picks go through `pickCommand` in `App.tsx`, not straight to `pty_write`. `pendingCmdRef` holds the template while it sits untouched at the prompt. `TerminalPanel` clears it on any keystroke (`onUserInput`). While it is set, `assignPathVar` and `handleNavigate` rewrite the line with `rewritePromptLine`: Esc, a 60 ms pause (else ConPTY reads Esc+char as Alt+char), then the new text. `handleNavigate` clears the line before its `cd`, so the cd is never glued onto a half-typed command. Don't send Esc and text in one write.
- Verified in the real app with Playwright (assign, rewrite, cd with a pending line, typing stops rewrites).

**Local time (`src-tauri/src/localtime.rs`).** The modified date column, `filedate:` and zip timestamps all use local time, converted through Win32. Use `localtime::from_unix` for any new date display.

**Admin elevation.** `is_admin` checks elevation with `net session`. `relaunch_as_admin` starts a new instance through `Start-Process -Verb RunAs` and then calls `process::exit(0)`. `relaunch_as_normal` duplicates the Explorer shell's token and calls `CreateProcessWithTokenW`, falling back to launching through `explorer.exe`. Both relaunch paths pass the current folder as the CLI argument, quoted with `quote_path_arg`. The `explorer.exe` fallback can't pass arguments, so that path opens the default folder. Both sides call `AllowSetForegroundWindow`. On startup the frontend calls `force_window_to_front` and a series of timed focus/`setAlwaysOnTop` steps so the relaunched window comes to the front.

**UI conventions.**
- Monochrome theme built on CSS variables (`--bg-panel`, `--text-muted`, `--border-color`, `--accent`, …) in `src/index.css` / `src/App.css`. Light mode is the `.light-theme` class on `.app-container`.
- The terminal's colors are set separately in the xterm `theme` option.
- Styling is mostly inline `style={{}}` plus these classes. Icons come from `lucide-react`.
- The app is locked to 100vh×100vw with `overflow: hidden`. Each panel scrolls on its own. Splitters are plain mouse handlers in `App.tsx`.
- Browser context menus are suppressed everywhere except inputs. The app's own right-click menus (`.context-menu`) are positioned by `useMenuPosition` in `src/useMenuPosition.ts`, which measures the menu before it's drawn and keeps it inside the window. Put `ref={menuPos.ref} style={menuPos.style}` on the menu and `menuPos.submenuClass` on submenus, not fixed x/y offsets.
- User preferences persist in `localStorage` under `boonsh_theme`, `boonsh_view_mode` and `boonsh_quick_access` (Quick Access holds at most 6 items).
- The terminal's Commands 💡 menu and the Settings dialog (gear icon, `SettingsPanel.tsx`) share one list. `App.tsx` holds it, loading and saving through `src/commands.tsx` under `boonsh_commands`. The groups are fixed (Basic, Network, System, Customize), and `loadCommandGroups` always returns them in that order. Users add, edit, delete and move the commands inside them. Each command's `insertText` is what gets typed at the prompt, and it keeps a trailing space for commands that take arguments.
- **Group view (`src/grouping.ts`).** `GroupSpec { column, buckets: Bucket[] }` list, saved under `boonsh_group` (`loadGroups` still reads the first version's single `bucket`, mapping its month / week / day to year + part), global (it applies to every folder and search until cancelled). It is separate from the sort stack, but the **layer order is the sort order**: `orderedGroups` sorts the grouped columns by their index in `sortLevels` (a grouped column outside the sort comes after, in canonical column order; `groupColumn` in `App.tsx` appends it to the sort so it normally has a number) and each layer uses that column's direction. `groupKey(col, buckets, item, details, today)` gives `{ id, label, sort }` or `null` (no value: the `(none)` group, always last); `BUCKETS` lists the ways each column can be grouped and `BUCKET_LABEL` the menu text. `layoutItems` returns `rows` (one `GroupHeader` per innermost group, or per collapsed ancestor, followed by its items; for the Details table) and `flat` (the items in view order minus those in collapsed groups; `App.tsx` uses it as `sortedItems`, so Ctrl+A, Shift ranges and the status bar only see what is visible). A layer with a single group is dropped; inside the innermost group `compareItems` runs with only the sort levels that are not layers. A `GroupHeader` is one line: `labels[]` / `ids[]` are the path through the layers (`depth` = its last index), rendered as `label > label`; a click on the `>` after label k toggles `ids[k]` (a parent), a click on the line toggles its own `id`; when an ancestor is collapsed, `layoutItems` emits ONE line for it (`collapsed: true`, labels up to that ancestor, shown with a trailing down arrow) and skips everything below. No counts on screen (`count`/`bytes` are only for the tooltip). `itemsInGroup(rows, headerIndex, level)` returns the files of any level of a line for the right-click "Select"; `topGroupIds` feeds "Collapse all". Collapsed group ids live in `collapsed` in `App.tsx` (memory only; cleared when the grouping changes). For the date columns `buckets` holds the ticked parts (`year`, `month`, `week`, `day`) in tick order and `datePartsKey` joins their labels and zero-padded sort values in that order (`[year, month]` -> "2026 May", `[month, year]` -> "May 2026", `[month]` -> "May"; week = ISO week via `isoWeek`, and the year part is the ISO year when week is ticked); `relative` stands alone; other columns use `buckets[0]`. `toggleBucket` is the pure click rule used by the header menu's "Group by" list (a submenu in `MainFilePanel`, `showGroupSub`, kept open while ticking; the numbers beside the ticks are `.group-order`). Header rows are `tr.group-row` with a sticky `td.group-cell` (deliberately plain: it keeps the generic `.file-table td` font and colours and only adds `position: sticky` and the panel's own `--bg-panel` background so rows scrolling underneath are covered; the user rejected a tinted band as harder to read, so do not add colours or weights; the `.file-table td` prefix in the selector is still needed to beat that generic style; every line sticks at `top: 28` px, under the column header) (`top` = header height + depth x 24; `overflow: visible` or the label would not stick sideways) and tiles / thumbnails just use `flat`. Hiding a column drops its grouping (`updatePrefs`). Pure logic is checkable with `node --experimental-strip-types` after copying `columns.ts` and `grouping.ts` to `.mts` and rewriting the `./columns` import.
- **Quick Access (`src/quickAccess.ts`, `QuickAccessBar.tsx`, Settings section `'quickaccess'`).** The bar's items are saved under `boonsh_quick_access` (max `QA_MAX` = 6; `parseSaved` accepts an empty list as a real choice, only a missing or broken value falls back to `defaultQuickAccess(get_quick_access())` = Home, Desktop, Downloads, Documents, C:). `App.tsx` keeps `quickAccess` plus `qaCandidates` (the backend's folders and drives, reloaded whenever Settings opens); `handleAddQuickAccess` / `handleRemoveQuickAccess` serve both the right-click menus and the Settings check boxes (`onQaToggle`). `settingsRows` builds the list: C:, Home, Desktop, Downloads, Documents, other drives, then custom folders that are in the bar. A custom folder that is unticked leaves the list (it is not remembered anywhere else). The 6-item limit is checked in the Settings pane first so it can show a message instead of the `alert()` the right-click path uses.
- **Frequently Accessed (`src/frequent.ts`, `components/FrequentPanel.tsx`).** `FrequentStats` (`keyOf(path)` -> `{ path, count, last }`) is saved under `boonsh_frequent`; `FrequentSettings` (`enabled`, `count` 3..10) under `boonsh_frequent_settings`. `App.tsx` calls `recordVisit` in an effect on `currentPath`, so every change of the open folder counts once (refresh and search keep the path, so they do not) and counting runs even while the panel is off. `topFolders(stats, count)` ranks by count, then recency; deleting an entry (`removeVisit`) leaves the next ones to fill the slots, which keeps the panel as long as the Settings number. A failed `list_directory` for a requested path also calls `removeVisit`. The rows show only the folder name (the visit count is in the tooltip, not on screen). The panel sits in the same left column as `FolderTree` (a flex column with the tree in a `flex: 1; minHeight: 0` wrapper); its `max-height` is 45% so the tree always keeps room. The Settings section is `'frequent'`; `openSettings` accepts it.
- **Columns and smart sort (`src/columns.ts`, pure and unit-checkable with `node --experimental-strip-types`).** `COLUMNS` lists every column (`detail: true` marks the ones read from file properties). `ColumnPrefs` (`order`, `visible`, `dateShow`, `dateSort`, `foldersFirst`) is saved under `boonsh_columns`; the sort is a list of `SortLevel { column, order }` under `boonsh_sort` (`loadSort` / `saveSort`). `App.tsx` keeps both (`updateSort`, `updatePrefs`; hiding a column drops its sort level) and sorts with `compareItems` in a `useMemo`: folders first if the pref is on, then each level, then the name. Empty values (`null` in `sortValue`) sort last in both directions. `sortClick` (plain click = one column, Shift/Ctrl = add / flip / remove), `sortSet` and `sortRemove` are the header actions. `MainFilePanel` draws the header from `visibleColumns(colPrefs)` (arrow + `.sort-rank` number, `headerMenu` on right-click) and each cell with `cellText`. The Files Column section of `SettingsPanel` edits the prefs.
- Default app in the Type column: `file_props::default_app` asks `AssocQueryStringW` for the friendly app name of an extension (the "open" verb) and treats an association that points at `OpenWith.exe` as none (Windows' "Pick an app" fallback; the text is localized, the exe is not). `get_default_apps` takes the unique extensions and returns `ext -> name` (empty = none). `App.tsx` keeps `appByExt`, asks once per new extension while the Type column is shown, and clears it on window focus so a changed Windows default shows up. `typeText` in `columns.ts` builds the label (`MP4 (VLC media player)`, `ENV File (-)`); sorting still uses `typeLabel` (extension only) so the order does not move when the apps arrive.
- Media properties: `src-tauri/src/file_props.rs` (`get_file_details`, the only use of the `windows` crate, enabled in `Cargo.toml` for Windows only) reads Dimensions, Length, Album, Artist/Actor, Genre and Rating through `SHGetPropertyStoreFromParsingName` and `IPropertyStore`, so the values match Explorer's. There is no Actor property in Windows: video files show `System.Music.Artist` as Actor, audio files show it as Artist (`kind_of` decides). `App.tsx` fetches in batches of 50 for the files that `hasMediaProps`, only when `needsDetails(colPrefs, sortLevels)`, and caches by `detailKey` (path + modified time); a newer list cancels the old batches (`detailsSeqRef`). Date Created is `created` / `created_timestamp` on `FileItem` (list and search results).
- Right-click submenus: `.context-menu-item` is `position: relative`, so a `.context-menu-submenu` opens level with its own row (it was at the top of the popup before). The Global Var submenu also nudges itself up in a layout effect (`varSubmenuRef` in `MainFilePanel`) when it would run past the bottom of the window. `SUBMENU_WIDTH` in `useMenuPosition.ts` matches the submenu's `max-width` (320).
- The search box is a `<textarea class="search-floating">` (2 rows) inside `.search-box`, a 360x26 wrapper: the wrapper keeps the header one line high while the textarea floats (absolute, `z-index` 1002) and is 46 px tall. It wraps (`pre-wrap`, `overflow-wrap: anywhere`) and scrolls; Enter is blocked and newlines are turned into spaces, so the query stays one logical line. The error/notice/status bubbles and `.search-help` are placed at `top: 52px` to clear it. Keep that offset if the box height changes.
- Keyboard shortcuts live in `App.tsx`: Ctrl+P toggles the preview, Ctrl+Shift+F toggles the file panel, F5 refreshes, Del recycles the selection, F2 opens Bulk Rename (2+ items selected), Ctrl+Z undoes the last bulk rename.
